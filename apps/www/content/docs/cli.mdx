`@aura-design/cli` is the on-ramp for Aura. It wraps Next.js scaffolding and the shadcn CLI with Aura registries, tokens, rules, skills, and optional project tooling.

Invoke it with:

```bash
pnpm dlx @aura-design/cli@latest <command>
```

The published binary name is `aura`.

## Quick start

**New Next.js app** with Aura fixtures:

```bash
pnpm dlx @aura-design/cli@latest init
```

**Existing Next.js app** (skips `create-next-app`):

```bash
pnpm dlx @aura-design/cli@latest setup
# or
pnpm dlx @aura-design/cli@latest setup --dir ./apps/web
```

See also [Installation](/docs/installation) for adding every registry component via `all.txt`.

## Commands

### `init`

Creates a Next.js app with `create-next-app`, then applies Aura to the new (or current) project root:

1. Writes `components.json` with `@aura` and `@aura-dev` registries
2. Generates light/dark Radix scales into `globals.css`
3. Runs `shadcn add` for `@aura/class-names`, `@aura/page-get-starter`, `@aura/css-main`, `@aura/rules`, and `@aura/skills`
4. Runs the same scaffolding as [`blueprint`](#blueprint), including [gdp-ts](/docs/gdp-ts) proofs

```bash
pnpm dlx @aura-design/cli@latest init
```

### `setup`

Same Aura apply step as `init`, for a project that already has a `package.json`. Does **not** run `create-next-app`.

| Option | Description |
| --- | --- |
| `-d, --dir <path>` | Project root (default: current working directory) |

```bash
pnpm dlx @aura-design/cli@latest setup --dir .
```

### `link`

Downloads the canonical Aura `components.json` (shadcn config with `@aura` registry URLs) into your project. Useful when you only need the registry config, not a full `setup`.

| Option | Description |
| --- | --- |
| `-o, --output <path>` | Output path relative to cwd (default: `components.json`) |

```bash
pnpm dlx @aura-design/cli@latest link
pnpm dlx @aura-design/cli@latest link --output ./apps/web/components.json
```

### `blueprint [projectDir]`

Scaffolds Aura project tooling into any repo with a `package.json`:

- The feature map: `wiki/obsidian-*/Feature-Map/Feature-Map.base` (suffix from the package name, first segment stripped), plus `.agents/rules/feature-map.mdc` and `.cursor/skills/update-feature-map/`. It is the only project documentation: one note per feature, updated in the PR that changes it. There is no progress log
- `wiki/obsidian-*/01-Identity/Image-Identity.md` for image generation
- `.cursor/skills/generate-brand-images/` (identity-aware Gemini landing images)
- Third-party [audits](/docs/audits) are not installed. Re-running blueprint deletes the Emil and Vercel skill folders an older CLI copied into `.cursor/skills/` and `.agents/skills/`
- The forms stack: `.agents/rules/components-forms.mdc`, `.cursor/skills/aura-forms/`, and the `@aura/form`, `@aura/field`, `@aura/use-dynamic-form`, and `@aura/web-validation` registry items (ajv, ajv-formats, ajv-errors). Missing rule and skill files are written, untouched older Aura copies are updated, and customized copies are kept unless you pass `--force`. Components are added only when missing and when `components.json` has the `@aura` registry
- A Cursor link: `.cursor/rules` → `../.agents/rules`. Cursor loads project rules from `.cursor/rules`. Blueprint moves any real files already in that directory into `.agents/rules/` and replaces the directory with the symlink, so the rules stay one copy
- `scripts/preflight.ts`
- Upstream [shadcn/ui skills](https://ui.shadcn.com/docs/skills) via `pnpm dlx skills add shadcn/ui` (`.agents/skills/shadcn`)
- `sonar-project.properties` plus Sonar-related scripts / devDependencies
- `.gitignore` and `.env.example` entries for Sonar / Gemini keys
- [gdp-ts](/docs/gdp-ts): `@gdp-ts/core`, the ESLint preset, the agent skill, a `typecheck` script when one is missing, and starter proofs (`session`, org role, project role, plan entitlement, and `deleteProject`)

Also runs automatically at the end of `init` and `setup`.

On repos bootstrapped by an older CLI, blueprint removes the Project Brain agent files it used to install: `.cursor/rules/self-documenting-system.mdc`, `.agents/rules/self-documenting-system.mdc`, `.cursor/skills/update-project-brain/`, `scripts/brain-progress.ts`, and the `brain:progress` script when it still has the Aura value. Existing wiki notes stay where they are. It also deletes the Emil skill folders and `react-best-practices` / `vercel-react-best-practices` from `.cursor/skills/` and `.agents/skills/`.

| Option | Description |
| --- | --- |
| `-f, --force` | Overwrite bootstrap files, a customized forms rule or skill, and `scripts/preflight.ts` if they exist |
| `--suffix <string>` | Override the `wiki/obsidian-<suffix>` vault suffix |

```bash
pnpm dlx @aura-design/cli@latest blueprint
pnpm dlx @aura-design/cli@latest blueprint ./apps/web --force --suffix my-app
```

> **Note:** The docs page [Agent blueprint](/docs/mcp-agent-blueprint) is an **agent runbook** (`Ejecuta` + URL). It is not this CLI command, though the runbook may invoke `aura blueprint` when scaffolding is missing.

### `colors`

`--accent` and `--gray` are the seeds. `--background` is an optional light canvas. The dark canvas is derived from the gray seed.

When `--accent` or `--gray` is omitted, the command prompts for the missing seed. It does not prompt for a background. When a flag value is not `#rgb` or `#rrggbb`, the command exits 1 and does not prompt.

The command prints a WCAG report. When the report contains a `fail` line, the command exits 1 and does not write `globals.css`. When the report contains a `warn` line and no `fail` line, the command still writes the file.

`:root:not(.light)` inside `@media (prefers-color-scheme: dark)` and `.dark` set the same custom properties.

| Option | Description |
| --- | --- |
| `--accent <hex>` | Accent seed |
| `--gray <hex>` | Gray seed |
| `--background <hex>` | Optional light canvas |

```bash
pnpm dlx @aura-design/cli@latest colors --accent "#f84657" --gray "#8c7375"
pnpm dlx @aura-design/cli@latest colors --accent "#4015ca" --gray "#7254cb"
```

The command writes the first of these files that exists. The candidates are `app/globals.css`, `src/app/globals.css`, `styles/globals.css`, and `src/styles/globals.css`. When none exist, it creates `app/globals.css`.

### `typography generate`

Interactive prompts for body size, small size, and a headline scale (ratio or explicit `h6`–`h1`). Writes a custom `typography.css` aligned with Aura’s fluid `clamp()` philosophy.

```bash
pnpm dlx @aura-design/cli@latest typography generate
```

### `spacing [target]`

Rewrites Tailwind spacing utilities in `.tsx` files from the default **4px** mental model to the closest **13px**-based token (Aura’s `--spacing`).

| Option | Description |
| --- | --- |
| `-d, --dir <directory>` | Scan root when `target` is omitted (default: `.`) |

```bash
pnpm dlx @aura-design/cli@latest spacing
pnpm dlx @aura-design/cli@latest spacing ./components
pnpm dlx @aura-design/cli@latest spacing --dir ./apps/web
```

## Adding components

After `init` or `setup`, install individual registry items with the shadcn CLI and the `@aura` namespace:

```bash
pnpm dlx shadcn@latest add @aura/button
```

There is no Aura command that adds every component. Use the newline-delimited list at [https://auradesignsystem.com/all.txt](https://auradesignsystem.com/all.txt).
