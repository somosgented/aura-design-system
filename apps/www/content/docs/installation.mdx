Install is the human path into the kit. What an agent should read, and the rules it follows, is on [Get started](/docs).

## New app

```bash
pnpm dlx @aura-design/cli@latest init
```

`init` creates a Next.js app, then applies Aura:

1. `components.json` with the `@aura` and `@aura-dev` registries
2. Light and dark accent and gray scales in `globals.css`
3. `@aura/class-names`, `@aura/page-get-starter`, `@aura/css-main`, `@aura/rules`, and `@aura/skills`
4. Blueprint scaffolding, including [gdp-ts](/docs/gdp-ts) proofs

`@aura/rules` writes root `DESIGN.md` and the Cursor rules. `@aura/skills` writes the consumer skills under `.cursor/skills/`.

## Existing app

```bash
pnpm dlx @aura-design/cli@latest setup
```

`setup` runs the same apply step and skips `create-next-app`. Pass `--dir` when the app is not the current directory.

```bash
pnpm dlx @aura-design/cli@latest setup --dir ./apps/web
```

An agent on a project that is already partly set up should follow the [agent blueprint](/docs/mcp-agent-blueprint) and install only what is missing.

## One component

```bash
pnpm dlx shadcn@latest add @aura/button
```

There is no command that adds every component at once. The current names, one per line, are at [all.txt](https://auradesignsystem.com/all.txt).

Flags for `link`, `colors`, `typography`, `spacing`, and `blueprint` are on the [CLI](/docs/cli) page.
